# Игрок в Godot 4 — как подключить

## 1. Сцена

```
Player (CharacterBody3D)   ← Player.gd
├── CollisionShape3D       ← CapsuleShape3D: радиус 0.28, высота 1.7
└── Head (Node3D)          ← позиция Y = 1.62
    └── Camera3D           ← FOV 75
```

Радиус капсулы 0.28 м — это те же 11 пикселей из прототипа при клетке 2.4 м.
Коридор шириной в клетку остаётся проходимым, но плечи задевают углы, и это правильно.

## 2. Действия (Проект → Настройки проекта → Ввод)

| Действие | Клавиши |
|---|---|
| `forward` / `back` | W / S |
| `left` / `right` | A / D |
| `turn_left` / `turn_right` | ← / → |
| `run` | Shift |
| `quick_turn` | Q |
| `flash` | Пробел |

`ui_cancel` (Esc) уже есть — он отпускает мышь.

## 3. Чего тут намеренно НЕТ

**Ручной проверки столкновений.** В прототипе были `collides`, `tryMove` и страховка
`unstick`, которая выталкивала игрока из камня. Всё это — обход того, что в HTML нет
физики. В Godot есть `move_and_slide`, и переносить туда наши костыли не надо:
`unstick` появился из-за бага, когда катсцена вдавливала игрока в стену, а не из-за
дизайна. Если такой баг возникнет в Godot — лечить надо катсцену.

**Прыжка и гравитации.** Игра целиком на плоском полу.

## 4. Что беречь при настройке

Скорость игрока меняй свободно, но сохраняй отношения — они добыты замерами:

| | Доля от скорости игрока |
|---|---|
| Монстр в режиме охоты | 0.74 |
| Монстр в погоне | 0.91 |
| Погоня при максимальной ярости | **1.50** — жёсткий потолок |

Полтора — это предел, за которым убежать нельзя в принципе и лабиринт становится
коридором смерти. В прототипе потолка не было вовсе, и при большом счёте ошибок
монстр разгонялся до четырёх скоростей игрока.

Потолок ходьбы по шуму (`noise_walk_cap` = 0.55) тоже не поднимай: без него обычная
ходьба забивает шкалу за 2.5 секунды и вторая фаза наступает почти сразу.
